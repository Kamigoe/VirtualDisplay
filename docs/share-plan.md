# カーソルとクリップボードの共有：設計

`docs/roadmap.md` の 3.「ローカルでのカーソル描画、テキストのクリップボード共有」の設計。2026-11-16 確定。
通信仕様は `docs/protocol.md` の「カーソルとクリップボード」。

**状況**：フェーズ 1（Windows と Mac）は実装・試験済み（2026-11-16、`db8514b`。経過は `docs/mac-handoff-share.md`）。
Windows ではビルド・単体テスト・実際のクリップボードを使う試験（`cargo test --release -- --ignored clipboard`）が通り、
Mac でビルド（警告 1 件を修正）・インストールのあと、利用者の試験ですべて ○：カーソルが遅れずに付いてくる、形
（I ビーム・手・リサイズ矢印）とホットスポット、全画面 / ウィンドウ・HiDPI / 等倍での大きさ、F8 での切り替え、
クリップボードの双方向（日本語・複数行・約 400 KB）と 1 MiB の上限。LaunchAgent で動く `vdsend` でも
`NSCursor.currentSystem` で形が取れた。Ubuntu（フェーズ 2）は未着手。

## 目的

- 入力の統合（`docs/input-plan.md`）で、マウスは PC から絶対位置で送るようになった。ところがカーソルは Mac が
  映像に焼き込んでいるので、20〜30ms 遅れて付いてくる。PC 側で描けば遅れがなくなり、操作感が大きく良くなる。
- Mac と PC の間でテキストをコピー・貼り付けしたい（mac-input-cast にはなかった機能）。

## 決定事項

| | 項目 | 決定 |
|---|---|---|
| S1 | カーソルの描き方 | **PC の OS のマウスカーソルとして表示する**。形（矢印・I ビームなど）は Mac から変わるたびに受け取り、winit の `CustomCursor` にする。`vdview` が映像の上に描く方式より遅れがなく（OS が描く）、実装も小さい |
| S2 | F8 で OFF のとき | **映像への焼き込みに戻す**。Mac 側のマウスで操作してもカーソルが見える。ON に戻すと PC 側の表示に切り替わる |
| S3 | クリップボード | **テキストのみ、双方向・自動**。どちらかでコピーしたら、もう一方にも入る。F8 とは関係なし。`--no-clipboard` で無効 |
| S4 | 大きさ | **1 MiB まで**。制御メッセージの上限（64 KiB）を超える分は 60000 バイトずつに分けて送る |
| S5 | 安全 | 入力と同じ暗号化した経路（Secure）で送る。握手が成功した接続だけ。パスワード管理ソフトの「共有しない」印が付いた内容は送らない。接続した時点の中身は送らない（その後のコピーだけ） |

## 仕組み

### カーソル

- `vdview`：転送が ON（入力の認証が済み、F8 が ON）の間、CursorMode 1 を送る。OFF にしたら 0。
  CursorShape を受け取ったら、映像の拡大率（ウィンドウのピクセル ÷ 映像のピクセル）に合わせて CPU で拡大・縮小し
  （`client/src/cursor.rs`）、ウィンドウのカーソルにする。形を受け取るまでは今までどおり（全画面ではカーソルを隠す）。
  古い `vdsend` は形を送ってこないので、何も変わらない。
- `vdsend`：CursorMode 1 を受けたら、ScreenCaptureKit の `showsCursor` を `updateConfiguration` で切り（取り込みを
  作り直さない）、`NSCursor.currentSystem` を 60Hz で調べて、絵かホットスポットが変わったら CursorShape を送る
  （`DesktopShare.swift`）。仮想モニターの拡大率（HiDPI なら 2 倍）で描き、120 ピクセルを超えるものは縮める。
  接続が切れたら焼き込みに戻す。
- 割り切り：転送 ON の間に Mac 側のマウス・トラックパッドを動かしても、映像にカーソルは映らない
  （F8 で OFF にすれば映る）。Mac がカーソルを隠している（文字の入力中など）ことは今は伝えない（0 × 0 の形は仕様だけ用意）。

### クリップボード

- `vdview`（Windows、`client/src/clipwin.rs`）：専用のスレッドにメッセージ専用ウィンドウを作り、
  `AddClipboardFormatListener` で変化を受け取る。`CF_UNICODETEXT` を読み、CR LF を LF にして送る。
  Mac からのテキストは LF を CR LF にして書き、その書き込みによる変化（シーケンス番号）は送り返さない。
  依存は増やさない（Win32 を直接宣言）。
- `vdsend`（`DesktopShare.swift`）：ClipboardMode 1 を受けたら、`NSPasteboard.general.changeCount` を 0.25 秒ごとに調べる。
  受け取ったテキストを書いたら、そのときの `changeCount` を覚えて送り返さない。
- 1 MiB を超えるテキストは送らず、送り側のログに出す。

## フェーズ

1. Windows と Mac：カーソルとクリップボード（この文書）。Mac のセッションでビルド・試験。
2. Ubuntu：カーソルの試験（共通コード）とクリップボードの実装。Wayland は、フォーカスがあるときしか
   クリップボードを読み書きできない（GNOME はデータコントロール系のプロトコルを持たない）ので、
   winit が既に使っているクレート（`smithay-client-toolkit`）の上に乗る `smithay-clipboard` などを検討する。
